# Lab 4：文件系统与 I/O（含第七章问答）

## 功能总结

实现 linkat、unlinkat 和 fstat。硬链接使用多个目录项指向同一 inode，链接数由持久化根目录扫描得到，不改变磁盘 inode 布局。删除目录项后仅在链接数和打开描述数都为零时释放 inode 和数据块；空目录槽可以复用。保留前章的时间、匿名映射、spawn 和 stride 调度功能。

## 实现与边界

稳定 inode 编号由磁盘 inode 位置反算。fstat 返回 dev=0、ino、FILE 类型和实时 nlink，其余字节清零，并用检查权限的跨页复制写回。无效描述符返回 -1。link 拒绝同名、缺失源文件、无效新文件名及已存在目标。unlink 拒绝不存在路径，先移除名称，再依据打开引用决定立即或延迟回收。

链接计数与打开引用不同：两个路径是两条硬链接；两个独立 open 是两个打开描述；fork 共享同一 Arc<OSInode> 时不产生新的独立打开描述。只要一个打开描述还存在，最后一次 unlink 之后仍允许读写旧文件；创建同名新文件时不能提前复用旧 inode。磁盘数据和索引块通过原有 clear_size 回收，inode 位图另行释放；不伪造 nlink、不修改测例。

代价：本实现为每次元数据读取扫描扁平根目录，时间复杂度 O(目录项数)，换取磁盘格式兼容和无计数同步冗余；大目录系统应设计持久化 nlink 并处理日志一致性。

## 第六章问答：root inode

root inode 是命名空间入口。easy-fs 中 inode 0 为根目录，根目录数据保存名称到 inode 编号的目录项。open、exec、文件列表和本次 link/unlink 都依赖它查找文件，根目录本身也可通过直接、一级及二级间接块扩展。

如果 root inode 的大小、数据块指针、类型或目录项内容损坏，文件可能无法按名称访问，列表/查找可能读取错误位置，甚至因框架断言失败导致内核停止。文件数据和 inode 位图即使完好也不意味着名称关系可恢复；需要 fsck、备份元数据、日志或其他冗余。不能简单重建一个空根目录就声称恢复所有文件。

## 第七章问答

### 1. pipe 的实际应用

`cat sample.txt | wc -l`：shell 创建一个管道，把 cat 的标准输出重定向到写端、wc 的标准输入重定向到读端，然后关闭父子进程中不用的端点。cat 读文件并写入管道，wc 流式读取并统计换行符。所有写端关闭后 wc 读到 EOF，输出结果。`wc -l sample.txt` 也能完成同一工作，但前者展示了管道组合。注意它统计换行符数量，末尾无换行的不完整行不会额外加一。

### 2. 更易用的多进程通信

设计内核消息队列/邮箱：由内核分配队列 ID 或注册服务名称；进程持有具有权限的句柄，通过 send/recv 交换带发送者 ID 和消息类型的数据。一个接收队列可接收多个发送者，reply_to 标识回复地址，不必为每对进程创建独立管道。内核管理队列容量、阻塞唤醒、关闭和进程退出清理，支持按类型过滤及非阻塞返回。消息复制提供隔离；大数据可配合受控共享内存句柄和消息通知，显式同步其生命周期。这样每个服务维护少量邮箱即可，而不是建立 O(n²) 对等管道；代价是消息路由、访问控制及背压策略。
